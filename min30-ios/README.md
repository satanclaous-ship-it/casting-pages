# 30분 기록 — 네이티브 iOS 앱

웹 앱(`../tracker/`)과 같은 시스템을, 웹으로는 불가능한 것들을 붙여서 다시 만든 것.

### 컴파일 — GitHub의 macOS 러너가 검증합니다

작성 환경에 맥이 없어서, 푸시할 때마다 GitHub Actions가 `macos-15` 러너에서
Xcode로 빌드합니다 (`.github/workflows/ios-build.yml`). 에러가 나면 error 줄만
추려 잡 요약에 남기고, 에이전트가 그걸 읽어 고칩니다 — 사람이 터미널을 열어
로그를 옮길 필요가 없습니다.

### 로직 — 검증된 웹 구현과 대조

컴파일은 못 해도 **로직이 맞는지는 확인했습니다.** 웹 앱(`../tracker/`)은 실제
브라우저에서 74개 불변식으로 검증돼 있으므로, 이 Swift의 순수 로직을 그대로 옮겨
무작위 입력 1,200건으로 웹 구현과 1:1 대조했습니다 — 슬롯 계산, 자정 넘김 오프셋,
집계·기록률, 최고 집중 구간, 밀린 블록 판정.

이 대조로 실제 분기 1건을 잡았습니다: 평균 집중력이 동점일 때 웹은 **더 오래 유지된**
구간을 고르는데 Swift는 먼저 나온 구간을 유지하고 있었습니다. 지금은 양쪽이
1,200건 전부 같은 답을 냅니다.

또한 웹 QA에서 나온 데이터 정합성 버그 3건이 Swift에도 그대로 있어 함께 고쳤습니다
(간격 변경 시 과거 시간 부풀기, 기록률 100% 초과, 저장 실패를 성공이라 표시).

즉 **컴파일은 CI가, 로직은 대조가** 지킵니다.

### 실기기 동작 — 여기는 흔적으로 봅니다

컴파일과 로직은 위에서 지키지만, **실기기에서 실제로 어떻게 도는지는 확인할 수
없습니다** (작성 환경에 아이폰이 없습니다). 그래서 앱이 죽거나 굳었을 때 어디까지
갔는지 두 군데에 남깁니다.

**1. 앱 안 — 맥이 필요 없습니다.**
앱이 꺼졌다면 다시 열고 `설정 → 마지막 흔적`. 죽기 직전까지 지나간 자리가 그대로
남아 있습니다. 크래시는 메모리를 가져가지만 이미 디스크에 쓴 것은 못 가져갑니다.

**2. 맥 콘솔 — 실시간으로 보고 싶을 때.**

```bash
log stream --predicate 'subsystem == "com.satanclaous.min30"' --style compact
```

어느 쪽이든 이렇게 찍힙니다:

```
09:14:02.113  ▶︎ didReceive action=com.apple.UNNotificationDefaultActionIdentifier
09:14:02.114  ┌ didReceive.main
09:14:02.115  └ didReceive.main 1.2ms
09:14:02.402  ▶︎ scenePhase=active
09:14:02.410  ┌ pendingSlot→seat(600)
09:14:02.411  └ pendingSlot→seat(600) 0.4ms
```

읽는 법은 두 가지뿐입니다.

- **`┌` 에 짝이 되는 `└` 가 없다** → 거기서 막혔거나 거기서 죽었습니다.
- **`↻ ... ×200, ×400, ×600` 이 쏟아진다** → 뷰 갱신이 무한히 돌고 있습니다.
  화면이 굳는 건 같지만 원인도 고치는 법도 완전히 다릅니다.

`앱 시작` 줄 **바로 앞**이 지난번에 죽은 자리입니다.

os_log 는 잠금 없는 링버퍼고 파일 쪽도 수백 바이트라, 진단이 끝나도 그냥 둡니다.

## 맥북에서 시작하기 — 한 줄

터미널에 이거 하나만 붙여넣으세요. 소스를 받고, 프로젝트를 확인하고, 실제로
빌드까지 돌린 뒤 결과를 알려줍니다.

```bash
curl -fsSL https://raw.githubusercontent.com/satanclaous-ship-it/casting-pages/claude/30min-activity-tracker-5z988y/min30-ios/setup-mac.sh | bash
```

- **성공하면** 연결된(또는 같은 와이파이의) 아이폰에 바로 설치됩니다.
- **첫 한 번만** Xcode에서 `Signing & Capabilities` → `Team`을 본인 Apple ID로
  골라 주세요. 인증서가 키체인에 생기면 이후로는 스크립트가 알아서 서명합니다.
- **에러가 나면** 에러만 추려서 화면에 보여주고 **클립보드에 복사해 둡니다.**
  그대로 Claude에게 붙여넣으면 고쳐서 다시 올려드립니다. 그 다음 위 명령을
  한 번 더 돌리면 됩니다.

### 케이블 없이 (무선 설치)

한 번만 준비하면 이후로는 같은 와이파이에 있기만 하면 됩니다.

1. 아이폰을 **케이블로** 연결
2. Xcode → `Window` → `Devices and Simulators` (⇧⌘2)
3. 왼쪽에서 기기 선택 → **`Connect via network`** 체크
4. 케이블 제거

이후 위 명령을 돌리면 무선으로 잡아서 설치합니다. 아이폰 **잠금은 풀어** 두세요 —
잠긴 기기는 무선으로 응답하지 않습니다. 유선과 무선이 둘 다 잡히면 유선을 씁니다.

XcodeGen 외에는 아무것도 자동으로 설치하지 않습니다. 그것도 물어보고 진행합니다.

## 직접 열기

```bash
open min30-ios/Min30.xcodeproj
```

`Signing & Capabilities`에서 본인 Team만 고르면 바로 실기기에 올라갑니다.
번들 ID는 `com.satanclaous.min30` — 원하는 값으로 바꾸세요.

프로젝트 파일이 안 열리면 (손으로 쓴 `.pbxproj`라 가능성 있음):

```bash
brew install xcodegen
cd min30-ios && xcodegen generate
```

둘 다 안 되면 Xcode에서 새 iOS App 프로젝트를 만들고 `Min30/` 폴더를 통째로
끌어다 놓으면 됩니다. 소스에는 프로젝트 구조에 대한 의존이 전혀 없습니다.

## 웹으로는 못 하던 것

| | 웹 앱 | 네이티브 |
|---|---|---|
| 알람 신뢰성 | `.ics` 캘린더 우회 필요 | `UNCalendarNotificationTrigger` — OS가 직접 |
| **알림에서 바로 기록** | ❌ | ✅ 앱을 안 열고 잠금화면에서 |
| Siri · 단축어 | ❌ | ✅ App Intents |
| 데이터 영속성 | Safari가 지우면 사라짐 | 앱 삭제 전까진 안전 |
| 마이크 · 온디바이스 인식 | 브라우저 의존 | `SFSpeechRecognizer` 한국어 |

### 알림에서 바로 기록 — 이게 핵심

알림을 아래로 당기면 이 버튼들이 뜹니다:

- **최근에 한 것 3개** — 누르면 그 자리에서 그 블록이 기록됨. **앱이 열리지 않음.**
  iOS가 앱을 백그라운드로 잠깐 깨워 `didReceive response`를 돌리고 끝냅니다.
- **직전과 동일** — 같은 일을 계속 중일 때 한 번.
- **아이디어 적기** — 알림 위에서 바로 타이핑(`UNTextInputNotificationAction`).

세 개는 저장된 태그 목록이 아니라 **실제 기록에서** 뽑습니다. 관리할 목록이
따로 생기지 않고, 잠금화면 버튼이 늘 요즘 하는 일을 가리킵니다.

## 알람 예약 방식과 한 가지 제약

iOS는 앱당 **예약 알림 64개**까지만 허용합니다.

- **주말 알람 켬 (기본)** — 블록마다 *매일 반복* 트리거 1개씩, 총 31개.
  만료가 없어서 앱을 다시 안 열어도 영원히 울립니다. ✅
- **주말 알람 끔** — 요일별 트리거를 쓰면 150개가 되어 한도를 넘습니다. 그래서
  앞으로 며칠치 구체 날짜만 미리 걸고, 앱이 실행될 때마다(알림 액션으로 인한
  백그라운드 실행 포함) 다시 채웁니다. 알림에 반응만 해도 계속 갱신되지만,
  **며칠씩 앱을 한 번도 안 열면 알람이 끊길 수 있습니다.**

설정 화면에도 이 경고가 표시됩니다. 확실한 쪽을 원하면 주말 알람을 켜두세요.

## 낮에는 기록, 저녁에는 판단

하루에 해야 할 일이 두 가지뿐이도록 설계돼 있습니다.

**낮 — 30분마다 기록만.**
무엇을 했나 → `다음` → 집중력 → 저장. **분류는 묻지 않습니다.**
자동 분류가 제안으로만 조용히 들어가고 "미확인" 으로 남습니다.

**저녁 — 리뷰에서 한 번에 분류.**
`분류하기` 카드가 미확인 블록을 모아 보여줍니다. 제안이 맞으면
`제안대로 N개 전부 확인` 한 번, 틀린 것만 칩을 탭해 바꿉니다. 바꾼 표현은
기억해 다음부터 맞춥니다.

30분마다 분류를 결정하게 하면 결정 피로로 기록 자체를 안 하게 됩니다. 그리고
무엇이 진짜 레버리지였는지는 하루 전체가 보일 때라야 판단할 수 있습니다.

## 시간 분류 — 『원씽』 기준

| | 뜻 | 임팩트 |
|---|---|---|
| 원씽 | 이것만 하면 나머지가 쉬워지는 그 하나 | ✅ |
| 레버리지 | 성과로 이어지는 일 | ✅ |
| 배움 | 나중에 레버리지가 될 인풋 | |
| 유지 | 해야 하지만 성과는 아닌 80% | |
| 회복 | 의도한 쉼 · 몸 · 사람 | |
| 낭비 | 빨려 들어간 시간 | |

**분류가 곧 임팩트 판정입니다.** 그래서 "이게 임팩트였나?"를 따로 묻지 않습니다.

회복이 낭비와 분리된 것도 책을 따른 것입니다 — 켈러는 휴식을 먼저 캘린더에
박으라고 합니다. 의도한 쉼은 성과의 반대가 아니라 조건입니다.

무엇을 했는지만 적으면 분류는 앱이 붙입니다. 우선순위는
**내가 고쳐준 것 > 오늘의 원씽 > 예전에 같은 걸 어떻게 넣었나 > 키워드**.
매칭이 없으면 유지로 둡니다 — 성과 쪽으로 기울이면 스스로를 속이고,
낭비 쪽으로 기울이면 억울해집니다.
